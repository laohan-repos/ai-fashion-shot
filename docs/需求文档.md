# 学员版需求文档｜穿影 AI 服装视频工作台

## 1. 文档信息

- 项目名称：穿影（AI Fashion Shot）
- 项目类型：Codex Vibe Coding 实战项目
- 使用对象：参加 Codex Vibe Coding 实战课程的学员
- 文档版本：V1.1
- 当前阶段：MVP
- 目标终端：PC 端与手机端自适应 Web 应用

### 1.1 文档用途

本文档用于指导学员在**不查看成品源码**的前提下，使用 Codex 从零完成“穿影”项目。文档负责说明“要做什么、做到什么程度、如何验收”，不直接给出完整代码、数据库表结构或现成实现方案。

学员应按以下方式使用本文档：

1. 先让 Codex 阅读需求，列出业务对象、核心流程、前置依赖和不明确的问题。
2. 将需求拆分为小里程碑，每次只实现一个可以独立运行和验收的目标。
3. 编码前要求 Codex 说明实现计划和预计修改的文件，编码后检查实际变更。
4. 每个里程碑完成后运行项目，并在浏览器中按验收场景实际操作。
5. 让 Codex 协助排错，但学员必须理解问题原因和最终修改内容。
6. 通过 Git 保存阶段成果，提交信息应能说明本次完成的需求。

本课程不以“让 Codex 一次生成整个项目”为目标，而是训练学员持续完成“理解需求 → 制定计划 → 编码 → 验证 → 修正 → 提交”的开发闭环。

## 2. 项目背景

服装商家和内容创作者在制作商品展示内容时，通常需要准备模特、服装、拍摄场景和视频脚本，并协调多种制作工具。整个过程周期长、成本高，且素材和生成结果难以统一管理。

本项目希望构建一个本地优先的 AI 服装内容创作工作台，将模特和服装素材管理、AI 图片生成、图片版本管理和短视频生成整合到一条清晰的工作流中。

## 3. 项目目标

### 3.1 业务目标

- 降低服装展示图和短视频的制作门槛。
- 将分散的模特、服装和生成结果纳入统一的作品管理。
- 让用户通过明确的步骤完成从素材到视频的生产过程。

### 3.2 教学目标

学员完成项目后，应能够：

- 将业务需求拆分为可实施、可验收的开发任务。
- 使用 Codex 完成代码库调研、方案设计、编码、调试和验证。
- 构建包含前端、服务端接口和持久化数据的完整 Web 应用。
- 接入图片和视频生成模型，处理超时、失败和异步任务。
- 使用 Git 管理开发过程，并对最终交付结果进行验收。

### 3.3 课程实施边界

教师应提供：

- 本需求文档、页面交互说明和阶段验收清单。
- PC 端与手机端设计参考图。
- 用于课堂测试的示例模特图、服装图和视频脚本。
- 外部模型能力说明，以及可用的测试配置或 Mock 方案。
- 必要的开发环境说明，但不直接提供成品项目源码。

学员需要完成：

- 使用 Codex 创建项目、实现功能、排查错误并完成验收。
- 对 Codex 提出的方案进行判断，不直接接受未经验证的代码。
- 记录关键提示词、重要技术决策、失败尝试和解决过程。
- 独立演示完整业务流程，并能解释项目的主要结构和数据流向。

## 4. 目标用户

### 4.1 服装电商运营

需要快速为多套服装制作商品展示图和视频，关注效率、素材完整性和产出一致性。

### 4.2 时尚内容创作者

需要使用不同模特、搭配和场景快速生成社交媒体内容。

### 4.3 服装品牌或设计师

需要在实际拍摄前预览模特穿搭和场景效果。

## 5. 核心用户流程

1. 用户进入素材库，新建一组“模特 + 服装”搭配。
2. 用户上传现有素材，或通过 AI 生成所需的模特和服装图片。
3. 用户新建作品，并为作品选择一组搭配素材。
4. 用户根据模特参考图生成模特四视图。
5. 用户将多张服装素材合成为完整的白底穿搭图。
6. 用户选择模特、服装和拍摄场景，生成模特穿衣图。
7. 用户选择一张穿衣图和视频脚本，提交短视频生成任务。
8. 系统查询任务状态，并在任务完成后保存和展示视频。

## 6. 功能需求

### 6.1 导航与页面结构

| 编号 | 需求 |
| --- | --- |
| NAV-01 | 系统应提供“作品”“素材”“模型”三个主要入口。 |
| NAV-02 | 当前所在模块应有明确的选中状态。 |
| NAV-03 | 用户可以从作品列表进入指定作品的制作工作台。 |
| NAV-04 | PC 端应提供适合宽屏操作的固定导航；手机端应使用紧凑导航，并保证三个主要入口可直接到达。 |
| NAV-05 | 页面在常见 PC 和手机宽度下不得出现影响操作的内容遮挡、按钮截断或非必要横向滚动。 |

### 6.2 作品管理

| 编号 | 需求 |
| --- | --- |
| PRJ-01 | 用户可以创建作品，填写作品名称和简短描述。 |
| PRJ-02 | 用户可以查看作品列表、制作进度和最近更新时间。 |
| PRJ-03 | 用户可以修改作品名称和描述。 |
| PRJ-04 | 用户可以删除作品，删除前必须二次确认。 |
| PRJ-05 | 作品制作进度应根据已完成的生成步骤自动计算。 |

### 6.3 素材与搭配管理

| 编号 | 需求 |
| --- | --- |
| AST-01 | 用户可以创建、重命名和删除搭配分组。 |
| AST-02 | 每个搭配分组可以包含模特素材和服装素材。 |
| AST-03 | 用户可以一次选择多张图片进行上传。 |
| AST-04 | 系统至少应支持 JPG、PNG 和 WebP 图片。 |
| AST-05 | 用户可以删除单张素材，删除前必须确认。 |
| AST-06 | 用户可以输入描述，调用 AI 生成模特或服装素材。 |
| AST-07 | AI 生成的图片应自动保存到当前搭配分组。 |

### 6.4 图片编辑与版本

| 编号 | 需求 |
| --- | --- |
| IMG-01 | 用户可以预览素材原图。 |
| IMG-02 | 用户可以输入修改要求，根据原图或指定历史版本生成新版本。 |
| IMG-03 | 新版本不应覆盖原图。 |
| IMG-04 | 用户可以在原图和历史版本之间切换预览。 |
| IMG-05 | 界面应显示生成中、成功和失败状态。 |

### 6.5 模特四视图

| 编号 | 需求 |
| --- | --- |
| MOD-01 | 用户从作品已关联的搭配中选择 1～4 张模特参考图。 |
| MOD-02 | 系统根据参考图生成同一位模特的四视图。 |
| MOD-03 | 生成后应保留生成结果、参考素材和提示词。 |
| MOD-04 | 用户可以对四视图继续编辑，并在多个版本间切换。 |
| MOD-05 | 生成四视图后，当前作品的搭配素材应被锁定，防止后续结果来源不一致。 |

### 6.6 服装白底图

| 编号 | 需求 |
| --- | --- |
| CLT-01 | 用户可以从当前搭配中选择最多 6 张服装参考图。 |
| CLT-02 | 系统应将所选单品合成为一张完整的白底穿搭图。 |
| CLT-03 | 生成结果中的单品应尽量保持原有品类、颜色、版型、图案和面料特征。 |
| CLT-04 | 生成结果不应包含人物、衣架、文字或水印。 |
| CLT-05 | 系统应保留输出图像与源素材的关联。 |

### 6.7 模特穿衣图

| 编号 | 需求 |
| --- | --- |
| FIT-01 | 生成前必须存在可用的模特四视图和服装白底图。 |
| FIT-02 | 用户可以选择图片版本、服装图和拍摄场景。 |
| FIT-03 | 系统应提供多个预设场景，并允许输入自定义场景。 |
| FIT-04 | 生成结果应尽量保持人物身份、服装细节、场景光线和人物比例一致。 |
| FIT-05 | 用户可以保留多张穿衣图，并选择其中一张用于视频生成。 |

### 6.8 视频生成

| 编号 | 需求 |
| --- | --- |
| VID-01 | 用户可以为选定的穿衣图选择或编辑视频脚本。 |
| VID-02 | 用户可以选择输出画面比例。 |
| VID-03 | 系统提交视频任务后，不应阻塞用户浏览其他内容。 |
| VID-04 | 系统应区分已提交、生成中、成功和失败状态。 |
| VID-05 | 任务失败时应显示可理解的原因，并允许用户重试。 |
| VID-06 | 任务成功后，系统应下载视频至本地并在作品中播放。 |

### 6.9 模型配置

| 编号 | 需求 |
| --- | --- |
| CFG-01 | 用户可以为不同能力配置 API 地址、模型名称、API Key 和启用状态。 |
| CFG-02 | 用户可以测试配置的连接和认证状态。 |
| CFG-03 | 界面和查询接口不得返回已保存的完整 API Key。 |
| CFG-04 | API Key 不得以明文存储在项目源码或版本库中。 |
| CFG-05 | 配置不完整或模型未启用时，生成操作应被阻止并显示提示。 |

## 7. 数据需求

系统至少需要管理以下数据对象：

- 作品：名称、描述、关联搭配、创建时间、更新时间和制作进度。
- 搭配分组：名称、创建时间和所属素材。
- 素材：类型、名称、图片数据、所属分组和创建时间。
- 图片版本：来源图片、编辑要求、图片数据和创建时间。
- 图片生成结果：作品、来源素材、提示词、图片数据和更新时间。
- 视频任务：作品、来源图片、脚本、远程任务标识、任务状态、失败原因和输出文件。
- 模型配置：能力类型、API 地址、模型名称、密钥和启用状态。

页面刷新或应用重启后，已保存的作品、素材和生成结果不应丢失。

## 8. 交互与状态要求

- 所有耗时操作都必须有加载状态，加载期间应防止重复提交。
- 创建、修改、删除和生成完成后应给出结果反馈。
- 错误信息应告诉用户发生了什么，避免只显示“操作失败”。
- 生成失败不得覆盖或删除之前的成功结果。
- 用户进入需要前置结果的步骤时，系统应明确提示还需要完成什么。
- 界面主要操作应支持键盘访问，图片和表单应具有可理解的标签。

## 9. 非功能需求

### 9.1 性能

- 作品列表和素材列表在本地环境中应能正常响应。
- 大图片和视频不应被直接嵌入页面源码。
- 外部模型请求必须设置合理的超时。

### 9.2 可靠性

- 数据写入失败时，不应留下明显的半完成状态。
- 删除包含多类关联数据的对象时，应保证关联数据处理一致。
- 远程视频任务短暂查询失败时，不应立即将任务标记为最终失败。

### 9.3 安全

- API Key、本地数据库、生成结果和环境变量不得提交到 Git 仓库。
- 服务端必须对文件名、数值 ID、图片类型和请求参数进行校验。
- 用户可配置的远程地址必须限制协议和可访问范围，不得允许借此访问本机或内网敏感服务。
- 如果应用部署到非本机环境，必须在上线前增加身份验证和访问控制。

### 9.4 可维护性

- 页面、业务组件、数据访问和外部模型调用应保持清晰边界。
- 重复的请求构建、错误处理和结果下载逻辑应尽量复用。
- 项目应包含启动方式、环境要求、数据目录和模型配置说明。

## 10. MVP 验收标准

同时满足以下条件时，项目可视为完成 MVP：

1. 应用可以按文档说明在本地成功启动。
2. 用户可以创建作品和搭配分组。
3. 用户可以上传模特与服装图片，刷新页面后数据仍存在。
4. 用户可以配置并测试图片和视频模型连接。
5. 完整走通“四视图 → 白底图 → 穿衣图 → 视频”流程。
6. 生成的图片和视频可以在应用中查看。
7. 图片编辑会新建版本，不会覆盖原图。
8. 超时、认证失败、生成失败和数据不完整均有可理解的界面提示。
9. `npm run build` 可以成功执行。
10. Git 仓库中不包含 API Key、本地数据库、生成素材和构建缓存。
11. 在 1440×900 的 PC 视口下，主要页面布局完整，核心操作无需横向滚动。
12. 在 390×844 的手机视口下，可以完成作品浏览、素材选择和生成流程，主要按钮不得被遮挡或超出屏幕。

## 11. 项目范围外

MVP 阶段不要求实现：

- 用户注册、登录和多租户管理。
- 团队协作、审批和评论。
- 支付、订阅、计费和用量统计。
- iOS、Android 等移动端原生应用；手机端自适应网页仍属于本期范围。
- 正式生产环境的高可用部署。
- 大规模对象存储和 CDN 分发。
- 自动发布到电商或社交媒体平台。

## 12. 建议实施里程碑

| 阶段 | 目标 | 核心产出 |
| --- | --- | --- |
| M1 | 产品骨架 | 项目初始化、导航、作品列表静态页面 |
| M2 | 本地数据 | 作品管理、搭配分组、素材上传与持久化 |
| M3 | 模型配置 | 多模型配置、密钥存储、连接测试 |
| M4 | 图片工作流 | 素材生成、图片编辑、四视图和白底图 |
| M5 | 穿衣图 | 模特、服装和场景组合生成 |
| M6 | 视频工作流 | 异步任务提交、状态查询、文件保存与播放 |
| M7 | 交付与质量 | 构建验证、安全检查、重构、README 和 Git 提交 |

## 13. 学员交付物

- 可运行的项目源码。
- 内容清晰的 README。
- 不包含敏感信息和运行数据的 Git 仓库。
- 一份需求与实现对照清单。
- 一份关键 Codex 对话或提示词记录。
- 一份项目复盘，说明重要技术决策、遇到的问题和改进方向。
- 一段完整流程演示或现场演示。

### 13.1 Codex 协作记录要求

关键开发阶段至少保留以下记录：

- 需求理解：学员如何让 Codex 复述需求、识别依赖和提出问题。
- 实施计划：Codex 给出的任务拆分，以及学员最终采用或调整的方案。
- 代码审查：每个阶段修改了哪些文件，是否存在超出需求的改动。
- 调试过程：至少记录一个真实错误、排查过程、根因和修复结果。
- 验收过程：构建命令、关键页面截图和完整业务流程验证结果。

记录的目的不是收集大量聊天内容，而是证明学员能够有效指挥、检查和纠正 Codex 的工作。

## 14. 需要在开发中决定的问题

以下内容不在需求文档中预先规定，由学员与 Codex 在实施过程中调研并做出选择：

- 页面和组件的具体拆分方式。
- 数据库表结构和迁移方案。
- 图片与视频文件的具体存储方式。
- 外部模型调用的封装边界。
- 状态管理、轮询和错误恢复方案。
- 组件库、样式组织和响应式策略。
- 测试范围与具体测试工具。

学员应对关键选择记录理由，并通过可运行结果和验收标准证明方案有效。
