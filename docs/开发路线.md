# 学员版开发路线｜使用 Codex 从零实现穿影

## 1. 路线说明

本路线用于指导学员使用 Codex，从空目录开始完成“穿影”AI 服装视频工作台。

配套文档：

- `需求文档.md`：定义要实现的功能和最终验收标准。
- `页面交互说明.md`：定义页面结构、操作反馈和异常状态。
- PC 端与手机版设计图：作为布局和视觉还原参考。

学员不得直接复制成品仓库代码。教师应以需求、设计、示例素材和阶段验收结果作为输入，让学员自己指挥 Codex 完成实现。

教学重点不是记忆框架 API 或复制老师的代码，而是学会以下完整开发循环：

> 理解需求 → 拆分任务 → 与 Codex 讨论方案 → 小步实现 → 运行验证 → 修复问题 → Git 提交 → 阶段复盘

开发过程分为 8 个阶段，每个阶段都产出一个可独立运行、可验收、可回退的版本。

## 2. 建议周期

| 阶段 | 主题 | 建议课时 | 阶段产出 |
| --- | --- | ---: | --- |
| 0 | 环境与 Codex 协作 | 2 | 可运行的空项目 |
| 1 | 产品骨架与界面 | 4 | 可浏览的静态原型 |
| 2 | SQLite 与作品管理 | 4 | 可持久化的作品列表 |
| 3 | 素材库与文件上传 | 5 | 可用的搭配素材库 |
| 4 | 模型配置与安全 | 4 | 可配置、可测试的模型连接 |
| 5 | AI 图片生成工作流 | 6 | 四视图、白底图和穿衣图 |
| 6 | 异步视频生成 | 5 | 可查询状态和播放的视频任务 |
| 7 | 测试、重构与交付 | 4 | 可演示的 MVP 和完整仓库 |

总计约 34 课时。可根据学员基础调整为 4～8 天集中实训，或 8～12 周课程。

### 2.1 每阶段课堂节奏

每个阶段建议采用相同的课堂结构：

| 环节 | 建议占比 | 学员行为 | 教师关注点 |
| --- | ---: | --- | --- |
| 需求讲解 | 10% | 明确本阶段输入、输出和边界 | 学员是否理解业务目的 |
| 方案讨论 | 15% | 让 Codex 调研仓库并提出计划 | 是否先分析、后编码 |
| 小步实现 | 45% | 分任务调用 Codex，持续检查改动 | 是否出现范围膨胀 |
| 运行验收 | 20% | 在 PC 与手机视口实际操作 | 是否只看代码、不跑功能 |
| 提交复盘 | 10% | 检查 diff、提交 Git、记录经验 | 是否能解释代码与决策 |

## 3. 全程开发规则

### 3.1 每个任务的固定流程

1. 阅读需求，圈定本次任务范围。
2. 让 Codex 先检查当前仓库，不立即修改代码。
3. 让 Codex 说明实现方案、影响文件和验证方式。
4. 一次只实现一个明确功能。
5. 启动应用，由学员在浏览器中操作验收。
6. 检查 Git diff，确认没有无关改动和敏感信息。
7. 运行与改动风险匹配的检查。
8. 创建一个语义清晰的 Git 提交。
9. 记录本轮提示词、问题、修复方式和个人收获。

### 3.2 学员不应直接接受的结果

- Codex 没有阅读需求就创建的大量代码。
- 无法说明作用的依赖或配置。
- 没有运行或验收过的功能。
- 为了解决局部问题而重写大量无关代码。
- 将 API Key、数据库、生成素材或个人信息加入 Git。

## 4. 阶段 0：环境与 Codex 协作

### 阶段目标

- 完成开发环境检查。
- 理解 Codex 在代码库中的工作方式。
- 建立项目仓库、协作规则和首次提交。

### 学员任务

1. 检查 Node.js、npm、Git 和 ImageMagick。
2. 创建空的 Next.js App Router 项目。
3. 阅读 `需求文档.md`，列出不明确的业务问题。
4. 阅读 `页面交互说明.md` 和 PC、手机版设计参考图。
5. 与 Codex 共同制定 `AGENTS.md`。
6. 创建 `.gitignore`、`.env.example` 和初始 README。
7. 初始化 Git 仓库并创建首次提交。

### 推荐提示词

```text
请先阅读 docs/需求文档.md，不要写代码。
说明你对项目目标、核心用户流程和 MVP 范围的理解。
列出需要确认的产品问题，并给出建议的开发阶段。
```

### 验收标准

- `npm run dev` 能成功启动空项目。
- Git 仓库只包含项目文件。
- `.gitignore` 覆盖环境变量、依赖、构建缓存和本地产出。
- 学员可以解释 `AGENTS.md` 中每条规则的用途。

### Git checkpoint

```text
checkpoint-00-project-setup
```

## 5. 阶段 1：产品骨架与界面

### 阶段目标

- 建立页面导航和基础视觉系统。
- 先使用模拟数据完成主要页面。
- 理解从参考图到可运行界面的迭代方法。

### 学员任务

1. 实现作品、素材和模型三个页面入口。
2. 实现作品列表、顶部操作区和侧边导航。
3. 实现四步制作工作台的页面骨架。
4. 为列表和工作台增加加载、空数据和错误状态。
5. 检查按钮、表单、焦点和键盘导航。
6. 同步实现 PC 与手机端布局，不把响应式适配留到项目最后。

### Codex 协作要点

- 先要求 Codex 根据参考图总结布局、间距、色彩和组件。
- 先完成一个页面，通过浏览器验收后再复用设计语言。
- 不接受“大概相似”，用具体的间距、对齐、尺寸和状态问题继续迭代。

### 验收标准

- 三个主要页面可正常切换。
- 作品页在有数据和无数据时都有完整界面。
- 四个制作步骤可切换，但暂不调用真实模型。
- 页面无明显溢出、遮挡和无法操作的按钮。
- 在 1440×900 的 PC 视口下，侧边导航、内容区和主要操作完整可见。
- 在 390×844 的手机视口下，导航、列表、表单和主要按钮均可正常使用。
- `npm run build` 成功。

### Git checkpoint

```text
checkpoint-01-ui-shell
```

## 6. 阶段 2：SQLite 与作品管理

### 阶段目标

- 为应用增加持久化数据。
- 实现第一个完整的前后端增删改查流程。
- 理解数据库事务、输入校验和错误状态。

### 学员任务

1. 设计作品数据对象和 SQLite 表结构。
2. 实现作品列表、详情、新建、编辑和删除接口。
3. 将作品页的模拟数据替换为真实数据。
4. 删除操作增加二次确认。
5. 根据作品完成状态计算制作进度。

### 推荐提示词

```text
请只实现作品管理的持久化和 API，不要提前实现素材或模型调用。
先说明数据模型、接口列表、输入校验和删除策略。
实现后验证新建、查询、修改、删除以及重启后数据保留。
```

### 验收标准

- 可以完成作品的增删改查。
- 空名称、过长名称和不存在的作品 ID 被正确处理。
- 刷新页面或重启应用后数据仍存在。
- 数据库文件未进入 Git。

### Git checkpoint

```text
checkpoint-02-project-crud
```

## 7. 阶段 3：素材库与文件上传

### 阶段目标

- 建立“搭配分组”业务模型。
- 完成图片上传、保存、读取、预览和删除。
- 理解文件类型校验和关联数据删除。

### 学员任务

1. 设计搭配分组、素材和素材版本数据模型。
2. 实现搭配分组的新建、重命名和删除。
3. 实现模特和服装图片的多文件上传。
4. 实现图片读取接口，不将大量二进制数据嵌入 JSON。
5. 实现素材预览、删除确认和版本标识。
6. 为作品关联一个搭配分组。

### 必须讨论的设计问题

- 图片应保存在 SQLite BLOB 还是文件系统？
- 删除搭配时，其素材和历史版本如何处理？
- 作品已开始生成后，是否允许切换搭配？
- 上传文件应如何校验类型和大小？

### 验收标准

- 每个搭配可以同时保存模特和服装素材。
- 支持 JPG、PNG 和 WebP，不支持的文件有明确提示。
- 多图上传过程有状态反馈，不会重复提交。
- 删除后页面、数据库和关联数据状态一致。

### Git checkpoint

```text
checkpoint-03-asset-library
```

## 8. 阶段 4：模型配置与安全

### 阶段目标

- 将外部模型参数与代码解耦。
- 安全保存 API Key。
- 实现模型连接测试与可理解的错误分类。

### 学员任务

1. 实现图片生成、图片编辑和视频生成配置。
2. 配置项包含 API 地址、模型名称、API Key 和启用状态。
3. 使用本地密钥或环境密钥对 API Key 加密。
4. 实现“测试连接”功能，区分认证失败、超时和服务器错误。
5. 确保配置查询不返回完整 API Key。
6. 限制远程地址的协议和访问范围。

### 安全练习

让 Codex 针对以下问题审查当前实现：

- API Key 是否可能被前端或日志读取。
- 自定义 API 地址是否存在 SSRF 风险。
- 错误响应是否暴露本地路径或敏感配置。
- 配置和生成接口在部署后是否需要身份验证。

### 验收标准

- API Key 不以明文存储，不会出现在 Git diff 中。
- 修改配置时，留空 API Key 不会意外删除已保存密钥。
- 测试连接具有超时和明确的状态反馈。
- 模型未配置或未启用时，后续生成请求被阻止。

### Git checkpoint

```text
checkpoint-04-model-config
```

## 9. 阶段 5：AI 图片生成工作流

### 阶段目标

- 接入文生图和图生图服务。
- 处理图片上传、多图参考、结果下载和版本保存。
- 完成前三个 AI 制作步骤。

### 5A：AI 素材生成与编辑

1. 根据文字描述生成模特或服装素材。
2. 将远程图片或 Base64 结果转换为本地图片。
3. 将生成素材保存到当前搭配。
4. 根据编辑要求创建图片新版本。
5. 保留原图，支持原图与历史版本切换。

### 5B：模特四视图

1. 选择 1～4 张同一位模特的参考图。
2. 构建统一的四视图生成提示词。
3. 发起多图参考生成请求。
4. 保存原始结果、提示词和来源素材。
5. 支持继续编辑和版本删除。

### 5C：服装白底图

1. 选择最多 6 张服装单品图片。
2. 组装白底穿搭图提示词。
3. 生成完整的服装搭配图。
4. 使用 ImageMagick 统一最终输出比例和尺寸。
5. 保留源素材与结果的关联。

### 5D：模特穿衣图

1. 选择模特四视图版本和服装白底图。
2. 选择预设场景或填写自定义场景。
3. 生成指定场景下的全身模特穿衣图。
4. 保存多张结果，不覆盖之前产出。

### 提示词迭代记录

学员应为每类生成任务记录：

- 目标画面。
- 参考图顺序和作用。
- 必须保持的特征。
- 禁止出现的内容。
- 首次结果的问题。
- 修改后的提示词。
- 结果是否改善及原因。

### 验收标准

- 四视图、白底图和穿衣图均可生成并保存。
- 请求超时和远程错误有明确提示。
- 生成失败不会覆盖已存在结果。
- 所有结果都可追溯到作品、源素材和提示词。
- 连续点击生成按钮不会提交重复请求。

### Git checkpoint

```text
checkpoint-05-image-workflow
```

## 10. 阶段 6：异步视频生成

### 阶段目标

- 理解异步任务的提交、轮询和最终状态。
- 根据穿衣图生成短视频。
- 安全保存和读取视频文件。

### 学员任务

1. 为穿衣图提供多个视频脚本。
2. 提交包含首帧、脚本、比例和时长的视频任务。
3. 将远程任务 ID 和本地任务状态持久化。
4. 实现有限频率的状态轮询。
5. 正确区分已提交、运行中、成功、失败和取消。
6. 任务成功后下载视频并在页面播放。
7. 对文件名进行安全清理，确保输出不会逃离视频目录。

### 需要验证的异常情况

- 任务提交超时。
- 远程任务长时间运行。
- 某一次状态查询失败。
- 远程任务最终失败。
- 任务成功但视频下载失败。
- 页面关闭后再次进入作品。
- 同一作品存在多个视频任务。

### 验收标准

- 提交任务后页面仍然可以正常操作。
- 轮询不会因组件更新而创建多个重复定时器。
- 临时网络错误不会把任务标记为最终失败。
- 生成成功的视频可在本地播放。
- 自定义脚本名称无法造成路径穿越。

### Git checkpoint

```text
checkpoint-06-video-workflow
```

## 11. 阶段 7：测试、重构与交付

### 阶段目标

- 对照需求完成最终验收。
- 消除原型阶段的重复代码和明显安全风险。
- 形成可读、可运行、可演示的 Git 仓库。

### 学员任务

1. 逐项执行 `需求文档.md` 中的 MVP 验收清单。
2. 让 Codex 检查重复逻辑、过大组件和不清晰的模块边界。
3. 优先拆分高频修改或高风险模块，避免为了“更优雅”而全面重写。
4. 检查输入校验、访问控制、SSRF、路径穿越和密钥泄露风险。
5. 对核心数据逻辑和容易回归的功能增加必要测试。
6. 完善 README、环境变量示例、启动指南和故障排查。
7. 分别在 PC 与手机视口执行完整流程并保存验收截图。
8. 运行生产构建并清理 Git 工作区。
9. 准备 5～8 分钟的完整项目演示。

### 推荐审查提示词

```text
请审查当前项目，暂时不要修改代码。
对照 docs/需求文档.md 检查功能完成度，并重点检查：
1. API Key 和敏感数据泄露；
2. 路径穿越与 SSRF；
3. 输入校验和错误恢复；
4. 过大文件、重复逻辑和耦合；
5. 缺失的构建、测试和文档。
按严重程度列出问题，给出证据、影响和最小修复方案。
```

### 最终验收标准

- 完整生产流程可以从头到尾执行。
- `npm run build` 成功。
- 核心错误场景已实际验证。
- README 足以让新用户在不询问开发者的情况下启动项目。
- Git 工作区干净，历史中无密钥和生成素材。
- 每个阶段都有可辨识的提交或 checkpoint。
- 学员能说明至少三个关键技术决策及其取舍。

### Git checkpoint

```text
checkpoint-07-mvp
```

## 12. 可选挑战

完成 MVP 后，可以选择以下扩展：

- 将“批量生成”从 UI 模拟改为真实的队列任务。
- 增加任务暂停、取消、重试和失败恢复。
- 将图片与视频迁移到对象存储。
- 增加登录、权限与多用户数据隔离。
- 增加模型调用成本和用量统计。
- 增加作品导出、打包与分享。
- 增加 PWA 安装、离线提示和移动端相机上传。
- 接入更多图片或视频生成服务。

可选挑战应在单独分支中进行，避免影响已验收的 MVP。

## 13. 阶段复盘模板

每完成一个阶段，学员应回答：

1. 本阶段完成了什么？
2. 最初给 Codex 的任务是否足够清晰？
3. Codex 产生了哪些不符合预期的结果？
4. 通过什么证据定位问题？
5. 提示词或需求如何调整？
6. 运行了哪些验证？
7. 本阶段最重要的技术决策是什么？
8. 如果重新实现，会改变什么？

## 14. 最终演示顺序

1. 介绍项目背景与用户问题。
2. 创建一组模特与服装搭配。
3. 上传或生成模特和服装素材。
4. 创建作品并关联搭配。
5. 生成模特四视图。
6. 生成服装白底图。
7. 选择场景并生成模特穿衣图。
8. 提交视频任务并说明异步状态。
9. 展示一个错误场景及其处理。
10. 展示 Git 提交历史和项目复盘。

## 15. 完成定义

当以下条件全部满足时，课程项目完成：

- 功能符合 `需求文档.md` 的 MVP 范围。
- 学员可以独立演示完整用户流程。
- 学员能够解释代码的主要模块和数据流。
- 学员能够使用 Codex 诊断一个新问题，而不是只会重放课程提示词。
- 项目通过构建、功能、数据和安全验收。
- Git 仓库内容完整，不包含敏感信息和运行产物。
- 已完成项目复盘和最终展示。
